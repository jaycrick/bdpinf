# Recovery-Study Data Pipeline --- Precomputing Simulate-Then-Fit Validation Data

**The slowest notebooks in `qmd_scripts/validation/` were slow because of
inline simulation and MLE fitting, not plotting.** A review of
`_output/compile_times.json` found
`validation/single_epoch/06_bulk_inference.qmd` at 2492s (41.5 min) --- by far
the single largest render in the project --- running 4000 simulations and
3999 independent two-optimizer MLE fits inline, on every render.
`validation/single_epoch/07_asymptotic_consistency.qmd` runs 60,000
simulate-then-fit replicates (4 regimes x 15 observation times x 1000
replicates); the three `validation/multi_epoch/0{3,4,5}_bulk_inference*.qmd`
notebooks each run \~1000.
None of this work is cached between renders: every
`quarto render` re-simulates and re-fits from scratch.

## Existing precedent

The codebase already has a "generate once, persist, load" pattern for two
other kinds of expensive data, and this pipeline follows the same shape:

- **`bootstrap_samples/<subgroup>.npz`** --- generated by the application
  repo's (nt-manuscripts) standalone script
  `scripts/generate_bootstrap_kde_samples.py`, persisted via
  `save_bootstrap_samples`/`load_bootstrap_samples` in
  `analysis/bootstrap_date_density.py`.
- **`posterior_samples/<subset>.npz`** --- generated inline in the
  application repo's `ntvmr_birth_death_bayesian.qmd` (MCMC has to run
  somewhere), persisted via `save_posterior_samples`/`load_posterior_samples`
  in `inference/persistence.py`, and **reloaded, not recomputed**, by the
  application repo's `manuscript_survival_proportion.qmd`.
- **`analysis/asymptotic_consistency.py`** already went halfway there for
  `07_asymptotic_consistency.qmd`: its per-replicate simulate+fit logic was
  moved out of the Quarto script into an importable module.
  It just wasn't
  persisted or run ahead of time yet --- this pipeline finishes that job and
  extends the same move to the other four notebooks.

## What was added

**Persistence** --- `inference/persistence.py` gained a schema-agnostic
`.npz` round-tripper, `save_recovery_results`/`load_recovery_results`,
alongside the existing posterior-sample functions.
Unlike the fixed
`birth_rates`/`death_rates`/`epoch_end_times`/`epoch_names` schema used for
posterior samples, recovery-study tables vary in columns per study (a
single-epoch fit table has `birth_rate`/`death_rate`; a two-epoch table has
`epoch_1_birth`/`epoch_2_birth`/...), so each DataFrame column is stored as
its own named array (object dtype for non-numeric columns) rather than a
fixed set of keys.
Small scalar metadata (`n_simulated`, `n_kept`, the true
generative rates, ...) round-trips the same way bootstrap's metadata does.
No new dependency was introduced --- this stays with `.npz`, not parquet,
since pyarrow isn't currently a project dependency.

**New analysis modules**, mirroring `asymptotic_consistency.py`'s existing
extraction pattern:

- `analysis/single_epoch_recovery.py` --- `sample_single_epoch_ages`,
  `fit_single_epoch_replicate`, `run_single_epoch_recovery_replicate`, used by
  `06_bulk_inference.qmd`.
  `04_bulk_inference_single_rate.qmd`'s sampling step
  reuses `sample_single_epoch_ages` too, consolidating a second inline copy of
  the same sampling code that existed before this change.
- `analysis/multi_epoch_recovery.py` --- `run_two_rate_replicate` (for
  `03_bulk_inference.qmd`'s genuine two-epoch process),
  `run_single_rate_replicate` (for `04`'s single-rate-data-fit-with-two-epochs
  scenario), and `run_zero_birth_replicate` +
  `simulate_zero_birth_second_epoch` + `fit_zero_birth_replicate` (for `05`'s
  structural-zero-birth, shared-death, `Constraints`-fit scenario).

Both reuse existing helpers rather than duplicating them:
`validation_helpers.FitModelConfig`/`fit_single_model`/`has_ages_in_each_epoch`,
`single_epoch.extract_alive_ages`, `inference.Constraints`.

**Generation script** --- `scripts/generate_recovery_studies.py`, a Typer CLI
modeled directly on the application repo's
`scripts/generate_bootstrap_kde_samples.py`: `--study`
(repeatable; one of `single_epoch_bulk_inference`,
`single_epoch_asymptotic_consistency`, `multi_epoch_two_rate`,
`multi_epoch_single_rate`, `multi_epoch_zero_birth`; default: all five),
`--smoke-test` (scales every study to \~10 replicates to check the wiring
quickly), `--out-dir` (defaults to `<project_root>/recovery_samples/`).
Each
study's generator function reproduces the exact parameter grid and seeds
that used to live inline in its source notebook, runs it via
`joblib.Parallel`, and calls `save_recovery_results`.

```bash
# Full run (all five studies, production replicate counts):
uv run python scripts/generate_recovery_studies.py

# Just the single biggest win:
uv run python scripts/generate_recovery_studies.py --study single_epoch_bulk_inference
```

**Notebook changes** --- each of the five notebooks had its simulate+fit
cell(s) replaced with a `load_recovery_results(...)` call.
Downstream
plotting cells were adapted to read columns from the loaded DataFrame instead
of zipping raw fit-result dicts with raw age arrays, but are otherwise
unchanged.
One deliberate loss: the small "first 3 failed simulations" debug
print in `06`/`03`/`04` needed each failed replicate's raw age vector, which
the persisted tidy table doesn't retain (only scalar per-replicate summary
fields); each refactored cell has a comment pointing at the relevant
`analysis.*_recovery` module to reproduce a specific failure if needed.
The
summary/CI/spike-selection/debug-reproduction cells in
`07_asymptotic_consistency.qmd` are cheap (small aggregations and \~20 targeted
refits) and were left inline, unchanged.

**HPC pipeline** --- a new `scripts/generate_recovery_studies.slurm` (16
CPUs, since every study parallelizes internally via `joblib.Parallel`) runs
the full generation script.
`scripts/render_all.sh` now chains it *before*
`render_cpu_parallel.slurm` via the existing `--dependency=singleton`
job-name chain, since `render_cpu_parallel.slurm` renders the validation
notebooks that now load `recovery_samples/*.npz`.
`render_cpu_parallel.slurm`'s `--time` budget was reduced from 10h to 6h as
an interim, conservative estimate --- it still renders several notebooks
that simulate/fit inline and are out of scope for this change (see below);
retune once the refactored renders have been measured end-to-end.

`recovery_samples/` was added to `.gitignore`, matching `bootstrap_samples/`
and `posterior_samples/`.

## Explicitly out of scope: `01_simulation_checks.qmd`

`validation/multi_epoch/01_simulation_checks.qmd` runs 30,000 simulate calls
(10,000 replicates x 3 sampling methods) but **does no fitting** --- it's a
pure simulator-comparison/validation notebook.
It was excluded from this
pass for two reasons: its raw outputs are ragged per-replicate age arrays
rather than a natural tidy row (forcing them into `save_recovery_results`
would mean list-valued columns, which the current schema doesn't support
well), and it wasn't among the identified top time sinks.
If it turns out to
be worth precomputing later, it likely needs a different persistence shape
(e.g. a padded array or a long-format table with a replicate-id column)
rather than reusing `save_recovery_results` as-is.
